协议元语

类可以用一组固定名字的协议方法接管语言内建运算：+、==、 下标、for-in、字符串化。类型可知时，编译器在编译期把它们改写成普通方法直调—— 产物里没有任何运行期查找表，性能与手写代码等价。

1. 协议方法清单

协议集合是固定的，共 11 个：

协议方法 接管什么 约定
__add__ a + b、a += b 通常返回同型对象
__sub__ a - b、a -= b 同上
__mul__ a * b、a *= b 同上
__div__ a / b、a /= b 同上
__mod__ a % b、a %= b 同上
__eq__ a == b 返回真值（惯例 1/0）；结果是布尔，不参与链式推断
__index_get a[i] 越界行为自定（建议返回 null）
__index_set a[i] = v 同上
__for_keys for k in obj 返回键数组；优先于 __iter_len
__iter_len for i in obj 返回长度；配合 __index_get 即元素序列协议
__to_str output(obj)、"s" + obj、obj + "s" 返回字符串
!= 不在协议集里。需要不等语义时，自己实现一个函数或宏调用，不要指望 __ne__。

2. 绑定规则

2.1 类型可知 → 编译期静态绑定

当接收者的类型在编译期可确定时，运算/下标/迭代/输出会被直接改写成方法调用：

class Money {
    var cents = 0;
    func init(c) { this->cents = c; }
    func __add__(o) { return Money(this->cents + o->cents); }
    func __to_str() { return "$" + int_to_str(this->cents / 100); }
}

var a = Money(150);
var b = Money(250);
output(a + b);        // 改写为 a->__add__(b)

改写发生在编译期：产物里是一次普通方法调用，没有反射、没有字典查找、没有运行期类型判断。 解释器与原生可执行文件拿到的是同一份改写后的程序，因此两边的行为逐位一致。

2.2 类型未知 → 走运行期既有行为

接收者类型推断不出来时（例如函数参数、数组元素），运算不会报错，也不会走协议——它保持语言原本的运行期定价 （数字相加、字典取键、数组下标等）。

any_t func add_all(a, b) {
    return a + b;        // a/b 类型未知 → 运行期既有定价，不绑定协议
}
如何让类型可推断？让对象从构造点出发：var v = Vec2(1, 2)、 直接把构造结果赋给变量、经括号或同型三元分支传递、作为字段初始化器、方法体内通过 this 传递。 推断不出来就写显式函数，或在调用点手动调用协议方法（v->__add__(other)）。

2.3 协议未定义 → 保持既有静默定价

类没写对应协议方法时，行为与普通值完全一致（例如普通对象相加会得到运行期错误提示，而不是协议调用）。 这意味着加协议是纯增量：同一份代码，写不写协议都能跑，只是语义面不同。

3. 链式与复合赋值

五个算术协议方法按惯例返回接收者同型的对象，因此链式表达式可以继续静态绑定：

var s = Vec2(1, 2) + Vec2(3, 4) + Vec2(5, 6);   // 每次 + 都绑定 __add__

__eq__ 是例外：它的结果是布尔，不参与链式推断——a + b == c 里的 == 不会自动变成协议调用。

4. 容器协议：让对象可迭代

for-in 有两种协议形态，编译器按优先级选择：

形态 需要的方法 循环变量
键协议（优先） __for_keys() 键
序列协议 __iter_len() + __index_get(i) 下标 0 .. len-1
缺省 两者都没写 循环零次 
class Stack {
    var items = [];
    func init(vals) { this->items = vals; }
    func __iter_len() { return arr_len(this->items); }
    func __index_get(i) { return arr_get(this->items, i); }
}

var s = Stack([10, 20, 30]);
for (v in s) {
    output(v);        // 10 / 20 / 30
}

5. 协议 + 宏 = 完整面向对象能力

协议解决「行为」，宏解决「语法」。两者组合即可在纯 .qot 里长出接口与多态：

// 协议约定：任何实现者只要提供 speak() 就算满足
class Dog { func speak() { return "woof"; } }
class Cat { func speak() { return "meow"; } }

// any 调用点 = 运行期方法表分派（多态本体）
any_t func describe(obj) {
    return obj->speak();
}
output(describe(Dog()));
output(describe(Cat()));

把 obj->speak() 写成宏（如 speak!(obj)）就得到可复用的接口调用面， 见 编译期宏。

6. 命名与边界

  • 协议方法名固定为 __xxx__ 形式；其它 __ 开头的方法名不会被语言识别， 它们就是普通方法（但请避免使用该前缀，见类与对象的保留名说明）。
  • 协议只在类上生效：给普通值（数字、数组、字典）加同名方法没有意义。
  • 协议绑定不改变运行期错误契约：该报错的地方仍然报错，只是错误信息更贴近对象语义。
