运行环境：ScLoad / ScExec / ScSweep 在解释器侧可用（qguoat run）；编译成原生程序时没有这批函数，编译期会报「该内置在原生后端缺席」。

⚠️ 安全警告 · 使用Shellcode前必读

Shellcode 与 DLL 一样拥有完整的系统权限 —— 它可以读写文件、访问网络、修改内存、甚至格式化硬盘。
加载不可信的 .bin 文件等同于执行未知原生程序
仅当您完全理解风险且代码来源可信时，再使用此特性

🔬 什么是Shellcode？ 用途 & 风险

▼

Shellcode 本质上是 一段可直接执行的机器码（raw binary），无PE结构、不依赖特定加载器。
在QOT环境中，Shellcode通过 ScLoad 映射到可执行内存页，然后由 ScExec 直接运行。

  • 用途：极速算法（加密/排序/图像处理）、无文件攻击(渗透)、动态代码生成、底层硬件访问、绕过常规API钩子。
  • 文件格式：.bin 原始二进制流，无任何头结构。
    推荐使用 Donut 将 DLL/EXE 转换为位置无关的shellcode。
  • 潜在危害：
      • 勒索/破坏：删除文件、加密用户数据。
      • 木马后门：反向Shell、键盘记录、隐私窃取。
      • 穿透沙盒：由于直接执行系统调用，可能绕过部分安全软件。
      • 稳定性：错误的shellcode会导致宿主进程崩溃。
⚠️ 特别提示：.bin 文件可以被静态扫描，但高级shellcode会做多态/加密。即使扫描通过也不能保证绝对安全。
✅ 最佳实践：仅在自己编译的shellcode上使用；生产环境优先选择DLL或纯QOT脚本。

⚙️ QOT内置函数：ScLoad / ScExec / ScSweep

▼
函数 说明 参数 返回值
ScLoad 读取 .bin 文件，分配可读可写可执行内存，返回Shellcode实例对象。
path : string — shellcode文件路径
 ShellcodeInstance 对象 包含address,size,path
ScExec 在新线程中执行shellcode，支持超时控制（毫秒）。
instance : ShellcodeInstance — ScLoad返回的对象
timeout_ms : int (可选) — 默认5000ms，超过则强制终止线程
 true (执行完成/正常返回)
false (超时或异常)
ScSweep 释放shellcode占用的内存（VirtualFree），清理资源。
instance : ShellcodeInstance — 待销毁的实例
 true (释放成功) / 失败抛出异常
📘 示例：
var sc = ScLoad("calc.bin"); // 加载
ScExec(sc, 3000); // 等待最多3秒
ScSweep(sc); // 释放内存

💡 注意：ScExec 不会等待shellcode内部创建的其它子线程，仅等待主入口线程返回。
如果shellcode进入无限循环，超时后会强制终止线程，但可能遗留资源泄漏。

🍩 将C++ DLL (DllMain) 编译为 Shellcode · Donut 实战

▼

1️⃣ 编写一个标准DLL（用于转换）

// demo.cpp
#include <windows.h>

extern "C" __declspec(dllexport) int Add(int a, int b) {
    return a + b;
}

BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved) {
    if(ul_reason_for_call == DLL_PROCESS_ATTACH) {
        // 初始化/入口代码 — Donut会保留此逻辑
    }
    return TRUE;
}

编译指令（MSVC）：
cl /LD demo.cpp /Fe:demo.dll

2️⃣ 下载Donut

访问 https://github.com/TheWover/donut 下载最新版 donut.exe。

3️⃣ 转换为Shellcode (.bin)

# 最简单用法 (加载DLL并执行 DllMain + 导出函数表)
donut.exe -i demo.dll -a 2 -o payload.bin

# 参数说明：
# -f : 输入文件 (DLL/EXE)
# -a : 架构 1=x86 2=amd64
# -o : 输出 .bin 文件
# -e : 指定入口点 (默认调用DllMain)
# -p : 传递给shellcode的参数 (字符串)

生成 payload.bin 后即可用 QOT 加载：

var shell = ScLoad("payload.bin");
ScExec(shell, 5000); // 执行 DllMain 中的逻辑
ScSweep(shell);

⚠️ Donut 默认会将DLL的 所有导出函数 打包进shellcode，并在执行时通过哈希调用。也可以通过 -e 指定具体函数。

🔏 Shellcode 签名机制 · 追责溯源

▼

设计理念：签名不是为了"阻止"恶意代码执行，而是为了在发生恶意行为时能够追溯到签名者。

QOT 采用尾部签名方案 —— 签名信息追加在 .bin 文件末尾 512 字节，不影响 shellcode 本身执行。

📌 执行规则

未签名 → ScExec(instance) 拒绝执行，提示风险
未签名但强制执行 → ScExec(instance, timeout, true) 第三个参数为 true 即可执行
已签名 → ScExec(instance) 正常执行

请确保提供真实信息；虚假身份在追责时会被视为恶意行为。
签名 = 身份承诺 = 可追溯 = 可追责

🔄 如何选择：DLL 还是 Shellcode？

▼

📦 传统 DLL 方式 推荐 90% 场景

  • ✅ 加载简单：load("xxx.dll"); obj->func()
  • ✅ 支持导出函数，可直接调用特定API
  • ✅ 调试方便 (WinDbg / x64dbg 可直接分析)
  • ✅ 支持依赖其他DLL (VC运行时等)
  • ✅ QOT 自动管理加载/卸载 (无需手动释放)
  • ❌ 文件落地，易被静态扫描
  • ❌ 加载速度略慢于shellcode

⚡ Shellcode 方式 特殊场景

  • ✅ 无文件执行：纯内存，过AV监控
  • ✅ 极低加载开销（直接 mmap/VirtualAlloc）
  • ✅ 完全位置无关，适合注入/内存执行
  • ✅ 可结合 Donut 将任意PE转为shellcode
  • ❌ 无导出函数名，只能整体执行入口点
  • ❌ 必须手动调用 ScSweep 释放内存
  • ❌ 调试困难 (没有符号/没有模块加载)
  • ❌ 不支持 TLS / 异常处理完全位置无关

📌 决策指南

┌────────────────────────────────────────────────────────┐
│ 需要导出多个函数 / 长期复用 / 调试友好 → 选择 DLL │
│ 红队/渗透测试 / 注入第三方进程 → 选择 Shellcode │
│ 算法加速想要最小开销 → Shellcode (无导出表调用) │
│ 常规文件读写、GUI、网络请求 → DLL (配合内置函数更稳) │
│ 代码包含 .tls .ctors 复杂段 → 必须用DLL │
│ 需要传递结构体指针/回调 → DLL + export.func 更简单 │
└────────────────────────────────────────────────────────┘

性能差异：函数调用开销上，DLL 会多几次类型检查；Shellcode 几乎等于直接 call，但实际差距通常小于微秒级。
对绝大多数业务来说，优先选择DLL；仅当您确实需要“不落地”或“规避安全监测”时才使用shellcode。

🧪 完整示例：调用 C++ Shellcode 做整数加法

▼

步骤1 编写 C++ 文件 math.cpp

extern "C" __declspec(dllexport) int add(int a, int b) {
    return a + b;
}

BOOL WINAPI DllMain(HINSTANCE hinstDLL, DWORD fdwReason, LPVOID lpvReserved) {
    // Donut 转换后仍会调用此入口 (可选)
    return TRUE;
}

步骤2 编译DLL + Donut转shellcode

cl /LD math.cpp /Fe:math.dll
donut.exe -i math.dll -a 2 -o math.bin

步骤3 QOT脚本调用

// 注意：shellcode 整体执行，并没有名为"add"的导出函数。
// 如果想调用特定函数，需在 DllMain 中解析自身导出表或者使用 Donut 的 -e 参数。

var sc = ScLoad("math.bin");
output("shellcode 已加载，地址: " + strings(sc.address));
var ret = ScExec(sc, 3000);
if(ret) {
    output("shellcode 执行完毕 (DllMain 逻辑)");
} else {
    output("执行超时或异常");
}
ScSweep(sc);

🔔 核心提醒：shellcode 执行的是 DLL 的完整逻辑（DllMain + 可能的线程入口）。若想交互参数/返回值，需在C++内部实现进程间通信（如管道、共享内存），或使用导出函数 + 手动解析。
大部分场景下，直接使用 DLL 方式可避免这种复杂度。

📨 Shellcode 参数传递实战 · 环境变量通信法

▼

场景需求：Shellcode 没有导出函数，无法像 DLL 那样直接 obj->func(123)。
但可通过 环境变量、共享内存 或 管道 等进程内/进程间通信传递参数。
以下展示 环境变量通信法 —— 轻量、原生、无需额外库。

🟢 QOT

var file_shellcode = "SystemTest.bin";
set_env("SCC_ENV_FUNC_CODE", "3"); // 传递参数「打开计算器」
var shellins = ScLoad(file_shellcode);
var ok = ScExec(shellins, 5000);
if(ok) output("shellcode 执行完成");
else output("执行超时或失败");
ScSweep(shellins);
  • ✅ set_env(key, value) 设置进程环境变量
  • ✅ Shellcode 内通过 GetEnvironmentVariable 读取
  • ⚠️ 仅传递整数/短字符串，复杂数据建议用共享内存

🔧 C++ DLL (将被Donut转shellcode)

BOOL APIENTRY DllMain(HMODULE hModule, DWORD reason, LPVOID lpReserved) {
    if (reason == DLL_PROCESS_ATTACH) {
        char buf[8] = {0};
        GetEnvironmentVariableA("SCC_ENV_FUNC_CODE", buf, 8);
        int code = atoi(buf);
        switch(code) {
            case 0: ShutdownSystem(); break;
            case 1: RebootSystem(); break;
            case 2: HibernateSystem(); break;
            case 3: OpenCalculator(); break;
        }
    }
    return TRUE;
}
  • 🔧 完全位置无关代码 (PIC)，适合 Donut 转换
  • 📌 环境变量继承自 QOT 进程，shellcode 可直接读取

📦 其他参数传递方式对比

方法 复杂度 数据大小 适用场景
环境变量 ⭐ 低 ~32KB 整数/短字符串、控制码
共享内存 (CreateFileMapping) ⭐⭐⭐ 中 数MB 传递大量数据、图像、结构体数组
命令行参数伪造 ⭐⭐ 中 有限 模拟 exe 启动参数
DLL 导出函数 + Donut -e ⭐⭐ 中 灵活 需要直接传参并获取返回值
💡 实战建议：
• 对于“控制系统行为”（关机/弹计算器/网络请求），环境变量法最简洁。
• 若需要 shellcode 返回结果（如计算值），可让 shellcode 写回另一个环境变量，QOT 用 get_env() 读取。
• Donut 转换命令：donut.exe -i SystemTest.dll -a 2 -o SystemTest.bin
