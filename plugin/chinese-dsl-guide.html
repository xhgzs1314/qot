概述

QOT 是一个完整的脚本语言实现，包含词法分析器、语法分析器、AST 编码器、字节码编译器、虚拟机和内置函数库。其模块化设计使得扩展为中文编程语言或任意 DSL 变得异常简单。

核心思想： 你不需要重写整个编译器。只需要在关键扩展点注入你的语法规则和关键字映射。

本文将逐一分析 QOT 的各个模块，给出具体的扩展方案和代码示例，最终完成一个完整的“中文编程”扩展案例。

QOT 架构全景

QOT 的编译执行流程如下：

┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐

│  (.qot)     │    │ Lexer       │    │ Parser      │    │ Optimizer   │    │ Compiler    │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                                                    │
                                                                                    ▼
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  执行结果   │ <- │ 虚拟机执行  │ <- │ 字节码加载  │ <- │ 字节码文件  │ <- │ 编码/压缩   │
│             │    │ VM (C++)    │    │ Loader      │    │ (.qtc)      │    │ Encoder     │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘

扩展为中文编程或 DSL，主要涉及前 4 层（词法、语法、AST、字节码）和内置函数层。

模块 文件 扩展方式
词法分析器 token_char.py 添加中文关键字、运算符、标识符规则
语法分析器 grammar.py 添加/修改产生式规则，映射中文语法
AST 优化器 ast_encoder.py, astcomopt.py 通常无需修改，保持通用性
字节码编译器 bytecode.py 为新的 AST 节点添加编译规则
内置函数 builtin_func.py 注册中文命名的函数

第一层：词法扩展

词法分析器位于 token_char.py，负责将源代码字符串转换为 Token 流。这是扩展中文编程的第一站。

1.1 核心机制分析

词法器使用 ply.lex 实现，通过正则表达式匹配 Token。关键代码片段：

# token_char.py - 标识符匹配规则
def t_IDENTIFIER(self, t):
    r'[a-zA-Z_\u4e00-\u9fa5][a-zA-Z0-9_\u4e00-\u9fa5]*'
    return t

# 关键字集合
self.keywords = {"if", "else", "eif", "loop", "for", "in", "func", 
                 "return", "var", "const", "null", "stop", ...}
注意： 标识符正则 [\u4e00-\u9fa5] 已经支持中文字符！中文变量名、函数名开箱即用。

1.2 扩展中文关键字

要将英文关键字映射为中文，只需修改 keywords 集合：

# 修改 token_char.py 中的 __init__ 方法
self.keywords = {
    # 原有英文保留（兼容）
    "if", "else", "eif", "loop", "for", "in", 
    "func", "return", "var", "const", "null", "stop",
    # 新增中文关键字
    "如果", "否则", "否则如果", "循环", "对于", "属于",
    "函数", "返回", "变量", "常量", "空", "停止"
}

1.3 添加自定义运算符

QOT 的运算符在 t_OPERATOR 和 precedence 中定义。添加中文运算符（如“等于”、“大于”）：

# 在 t_OPERATOR 中添加
def t_OPERATOR(self, t):
    r'##|\+=|-=|\*=|/=|%=|==|!=|<=|>=|<<|>>|\+\+|--|->|&&|\|\||::|=|<|>|\+|-|\*|/|%|!|&|\||\^|~|\?|@|:|等于|大于|小于'
    # 映射中文运算符到内部表示
    if t.value == '等于':
        t.value = '=='
    elif t.value == '大于':
        t.value = '>'
    elif t.value == '小于':
        t.value = '<'
    return t
扩展原则： 尽量在词法层将中文 Token 映射为英文内部表示，这样可以最小化后续模块的修改。

第二层：语法扩展

语法分析器位于 grammar.py，使用 PLY 的 yacc 模块。这里是定义语言语法的核心位置。

2.1 语法规则结构

每个产生式对应一个以 p_ 开头的函数。例如条件语句：

def p_statement_if(p):
    '''statement : IF LPAREN expression RPAREN LBRACE statement_list RBRACE 
                  eif_clause_opt else_clause_opt'''
    p[0] = ('if_statement', p[3], p[6], p[8], p[9], get_line_number(p))

2.2 添加中文语法规则

要支持中文语法，有两种策略：

  • 策略A（推荐）： 新增中文产生式，复用相同的 AST 构建逻辑
  • 策略B： 直接修改英文产生式（会破坏兼容性）

以下是策略A的示例——添加中文条件语句：

def p_statement_if_chinese(p):
    '''statement : 如果 LPAREN expression RPAREN 开始 statement_list 结束
                  否则如果_子句_可选 否则_子句_可选'''
    p[0] = ('if_statement', p[3], p[6], p[8], p[9], get_line_number(p))

def p_eif_clause_chinese(p):
    '''eif_clause : 否则如果 LPAREN expression RPAREN 开始 statement_list 结束'''
    p[0] = ('eif_clause', p[3], p[6], get_line_number(p))

def p_else_clause_chinese(p):
    '''else_clause : 否则 开始 statement_list 结束'''
    p[0] = ('else_clause', p[3], get_line_number(p))

2.3 添加循环语句中文支持

def p_statement_while_chinese(p):
    '''statement : 循环 LPAREN expression RPAREN 开始 statement_list 结束'''
    p[0] = ('while_statement', p[3], p[6], get_line_number(p))

def p_statement_for_chinese(p):
    '''statement : 对于 LPAREN IDENTIFIER 属于 expression RPAREN 开始 statement_list 结束'''
    p[0] = ('for_statement', p[3], p[5], p[8], get_line_number(p))

2.4 函数定义的中文化

def p_statement_func_declaration_chinese(p):
    '''statement : 函数 IDENTIFIER LPAREN parameter_list_opt RPAREN 开始 statement_list 结束'''
    # 默认返回类型为 any_t
    p[0] = ('func_declaration', 'any_t', p[2], p[4], p[7], get_line_number(p))
注意： 添加中文语法后，需要同步更新 token 列表，将中文关键字加入 tokens 元组。

第三层：AST 与优化

AST 编码器（ast_encoder.py）和优化器（astcomopt.py）通常无需修改，因为它们操作的是节点类型（如 'if_statement'），而非具体的关键字。

3.1 AST 节点类型系统

所有 AST 节点使用元组表示，第一个元素是节点类型：

('if_statement', condition_ast, if_block_ast, eif_blocks, else_block, line)
('while_statement', condition_ast, body_ast, line)
('function_call', func_name, args, line)

无论你用什么中文关键字，最终都映射为这些标准节点类型。

3.2 添加自定义 AST 节点

如果你的 DSL 需要全新的语法结构（例如管道操作符 |> 或模式匹配），需要：

  1. 在 astcomopt.py 的 NODE_TYPES 中添加新类型
  2. 在优化器中添加对应的 _opt_xxx 方法
  3. 在字节码编译器中添加编译规则
# astcomopt.py - 添加新节点类型
NODE_TYPES = {
    # ... 原有类型 ...
    'pipeline': 'pipeline',  # 管道操作符
}

# 添加优化方法
def _opt_pipeline(self, node: Tuple) -> Tuple:
    _, left, right = node
    return _make_node('pipeline', self._optimize_node(left), self._optimize_node(right))
最佳实践： 优先复用现有 AST 节点类型，仅在必要时添加新类型。

第四层：字节码编译

字节码编译器位于 bytecode.py，负责将 AST 转换为虚拟机指令序列。

4.1 核心编译流程

Compiler._compile_node() 是核心方法，根据节点类型分发到不同的处理逻辑：

def _compile_node(self, node, code: VMCode, is_lvalue=False):
    node_type = node[0]
    if node_type == 'literal':
        # 编译字面量
    elif node_type == 'binary_op':
        # 编译二元运算
    elif node_type == 'if_statement':
        # 编译条件分支
    # ... 其他类型

4.2 为新 AST 节点添加编译支持

假设你添加了管道操作符 pipeline 节点：

elif node_type == 'pipeline':
    _, left_expr, right_expr = node
    # 编译左表达式，结果留在栈顶
    self._compile_node(left_expr, code)
    # 将栈顶值作为右表达式的隐式参数
    # 这里假设右表达式是一个函数调用
    self._compile_node(right_expr, code)

4.3 VM 指令扩展

如果新语法需要新的 VM 指令，在 VMInstruction 类中添加：

class VMInstruction:
    # ... 原有指令 ...
    PIPELINE = 70      # 管道操作指令
    PATTERN_MATCH = 71 # 模式匹配指令

然后在虚拟机实现（C++ 部分，位于 ot-asset/c/vmcshit/）中添加对应指令的处理逻辑。有关 VM 扩展的详细信息，请参考 VM 扩展开发文档。

第五层：内置函数扩展

builtin_func.py 定义了所有内置函数。要为中文编程添加中文命名的函数：

5.1 注册中文函数

# 在 _register_builtin_functions 方法中添加
def 输出(*args):
    formatted = [format_value_for_output(arg) for arg in args]
    print(' '.join(formatted))
    return None

def 输入(*args):
    prompt = ' '.join(map(str, args)) if args else ''
    return input(prompt)

# 注册到函数表
self.register_function('输出', 输出, (-1, ['any'], 'unknown'))
self.register_function('输入', 输入, (-1, ['any'], 'any'))

5.2 函数重命名（别名）

更优雅的方式是为现有函数添加中文别名：

# 为 output 添加中文别名
self.register_function('打印', self.functions['output'], (-1, ['any'], 'unknown'))
self.register_function('显示', self.functions['output'], (-1, ['any'], 'unknown'))

5.3 扩展类型系统内置函数

中文 DSL 可能需要特定的类型转换函数：

def 转为文本(*args):
    return str(args[0]) if args else ""

def 转为整数(*args):
    return int(args[0]) if args else 0

self.register_function('转为文本', 转为文本, (1, ['any'], 'string'))
self.register_function('转为整数', 转为整数, (1, ['any'], 'number'))

打造 DSL

基于 QOT 扩展 DSL 的通用方法论：

7.1 DSL 设计步骤

  1. 定义语法：明确 DSL 的关键字、运算符和语法结构
  2. 词法扩展：在 token_char.py 中添加新 Token
  3. 语法扩展：在 grammar.py 中添加产生式
  4. AST 映射：将 DSL 构造映射到标准 AST 节点
  5. 语义分析：在 grammar.py 的 SemanticAnalyzer 中添加检查
  6. 字节码生成：在 bytecode.py 中添加编译规则
  7. 运行时支持：在 builtin_func.py 中添加 DSL 专用函数

7.2 DSL 案例：配置语言

假设你需要一个描述 UI 布局的 DSL：

// UI 配置 DSL
页面 "主界面" {
    按钮 "确定" 位置(100, 200) 大小(80, 30)
    文本 "欢迎使用" 居中 颜色("#333")
}

实现方案：

  • 添加 Token：页面, 按钮, 文本, 位置, 大小, 居中, 颜色
  • 添加产生式，构建 AST 节点 ('ui_page', ...)
  • 在运行时将 AST 转换为实际 UI 组件（通过内置函数）

7.3 DSL 案例：数据查询语言

// 查询 DSL
从 "users.json" 中
选取 姓名, 年龄
满足 年龄 > 18
排序 年龄 降序
取前 10 条

这类 DSL 可以映射为：

# 等价的标准 QOT
query = load_json("users.json")
result = query.filter(fn(x) { return x.年龄 > 18 })
                .select(["姓名", "年龄"])
                .sort("年龄", desc=True)
                .limit(10)

测试与验证

8.1 单元测试

为你的扩展编写测试用例，验证词法、语法和运行时行为：

# test_chinese.py
from token_char import Lexer, TokenType

def test_chinese_identifier():
    lexer = Lexer()
    lexer.input("变量 名字 = \"小明\"", "test.qot")
    tokens = []
    while True:
        t = lexer.token()
        if t.type == TokenType.EOF_TOKEN:
            break
        tokens.append((t.type, t.value))
    assert ('IDENTIFIER', '变量') in tokens
    assert ('IDENTIFIER', '名字') in tokens

8.2 集成测试

使用 QOT 执行器运行中文脚本，验证输出：

常见问题

Q1: 扩展中文语法后，英文语法还能用吗？

A: 可以。只要保留原有的产生式，中英文可以共存。这使得 QOT 成为真正的双语语言。

Q2: 如何调试语法错误？

A: QOT 集成了完整的错误系统（error_system.py）。可以在 grammar.py 的 p_error 函数中添加自定义错误信息。

Q3: 性能会受影响吗？

A: 词法和语法层的扩展几乎不影响运行时性能。中文标识符在 AST 中仍然是字符串，字节码完全相同。

Q4: 能否在不修改核心代码的情况下扩展？

A: 可以通过继承机制扩展，但推荐直接修改源码，因为 QOT 是开源项目，你可以维护自己的分支。

Q5: 如何扩展 VM 指令？

A: 这需要修改 C++ 侧的虚拟机实现。详细内容请参考 VM 扩展开发文档。

Q6: 如何处理中文和英文的混合空格问题？

A: QOT 的词法器已经正确处理了 Unicode 空白字符，中文和英文之间无需特殊处理。

总结

QOT 的模块化设计使其成为DSL 扩展的理想平台。通过修改：

  • token_char.py —— 添加中文关键字和运算符
  • grammar.py —— 定义中文语法规则
  • builtin_func.py —— 注册中文函数

你可以在数小时内将 QOT 扩展为一门完整的中文编程语言或特定领域的 DSL。而 AST 优化器、字节码编译器和虚拟机的通用设计，保证了扩展后的性能和兼容性。
