现代化的 Direct2D 图形界面框架 v1.0

vg_* 已复活为 QOT 的官方图形界面——实现迁移到 ot-asset/c/wingui（Direct2D），解释器经 build/qotgui.dll 驱动、原生程序编译期直接链接， 双引擎行为一致。事件模型已改为轮询（vg_wait_event / vg_poll_event， 见 语言总述 22.1），旧 *_on_* 回调注册已移除——本手册中涉及 *_on_* 的段落仅作历史参考，其余 API 形态（创建 / 属性 / 取值）仍然适用。

历史背景：这套界面早期只实现在已弃管的旧字节码 VM 里 （ot-asset/c/vmcshit/gui_module.cpp），解释器侧曾是占位存根，须走 bstrust compile / run 历史路径——以下运行命令均为历史形态，现行跑法见上文。

🚀 快速上手

// 1. 初始化GUI框架
vg_init();

// 2. 创建主窗口
var window = vg_create_window("我的应用", 800, 600);

// 3. 设置渐变背景（这些窗口函数不传 window ID）
vg_set_window_bg_gradient([0.05, 0.05, 0.12, 1], [0.12, 0.08, 0.22, 1]);

// 4. 创建按钮
var btn = vg_create_button(300, 250, 200, 50, "点击我");

// 5. 定义回调函数
any_t func on_click() {
    output("按钮被点击了!");
    vg_button_set_text(btn, "已点击");
}

// 6. 绑定回调
vg_button_on_click(btn, on_click);

// 7. 显示窗口并运行
vg_show_window();
vg_run();

// 8. 清理资源
vg_uninit();

窗口操作

窗口管理
  • vg_create_window(title, width, height)创建窗口，返回窗口ID
  • vg_show_window()显示当前窗口
  • vg_run()运行消息循环（阻塞到窗口关闭）
  • vg_close_window()关闭并销毁当前窗口
  • vg_set_window_title(title)设置标题
  • vg_set_window_size(width, height)设置大小
  • vg_set_window_bg_gradient(start_color, end_color)设置渐变背景
示例代码
// 创建800x600窗口
var window = vg_create_window("标题", 800, 600);

// 紫色渐变背景（注意：不传 window！）
var start = [0.05, 0.05, 0.15, 1];
var end   = [0.15, 0.08, 0.25, 1];
vg_set_window_bg_gradient(start, end);

vg_show_window();
vg_run();
⚠️ 除了 vg_create_window，其余窗口函数都不接受窗口 ID。
它们内部一律直接操作「当前主窗口」（getMainWindow()），参数是从第 0 个开始数的。 所以下面这种写法是错的——旧版手册里就是这么写的，别再照抄： 
// ✗ 错：window 被当成了标题字符串
vg_set_window_title(window, "新标题");   // 标题变成了 "obj_3" 这种 ID

// ✗ 错：window 被当成了起始颜色，end 被完全忽略
vg_set_window_bg_gradient(window, start, end);

// ✓ 对
vg_set_window_title("新标题");
vg_set_window_bg_gradient(start, end);
vg_show_window(window) / vg_close_window(window) 多传一个参数不会出错（参数直接被忽略）， 但也没必要写。QOT 不检查实参个数，多写少写都不报错，写错位置就是静默地干错事—— 这一条在整个 GUI 模块里都成立。
所有 vg_create_* 的参数都是可选的，缺省时用内置默认值 （位置 50,50；按钮 200×40；文本框/下拉框 200×35；滑块 300×40；进度条 300×20； 列表框 200×150；卡片 250×200；标签页 500×400；加载动画 50×50；开关固定 60×30）。 所以 vg_create_button() 一个参数不给也能建出一个按钮来，不会报错。
但是：vg_create_window() 之前没调 vg_init()、 或者建控件之前没建窗口，函数会打印一行 [Error] 到 stderr 并返回 null——后面拿着这个 null 去操作控件，全都是静默失败。

回调函数说明

1. 事件自带的参数

每种控件触发时，VM 会自动往回调后面追加固定的几个参数。这一列是写死在 C++ 里的， 不是你能改的约定：

组件绑定函数回调函数签名事件追加的参数
按钮vg_button_on_clickany_t func on_click()（无）
复选框vg_checkbox_on_changedany_t func on_changed(checked)checked: bool — 勾选后的新状态
开关vg_toggle_on_changedany_t func on_changed(checked)checked: bool — 切换后的新状态
滑块vg_slider_on_changedany_t func on_changed(value)value: number — 当前值
下拉框vg_combobox_on_selectedany_t func on_selected(index, text)index: number（从 0 起）, text: string
列表框vg_listbox_on_selectedany_t func on_selected(index, text)index: number（从 0 起）, text: string
📌 只有这 6 个事件。文本框、进度条、卡片、加载动画、标签页这些控件 没有任何事件回调——框架里根本没有 vg_textbox_on_* 这种函数。 它们的值要在别的回调（比如按钮的 on_click）里用 vg_textbox_get_text() 这类函数主动去读。

2. 四种绑定写法

绑定函数的第 2 个参数（回调）认下面四种形式，可以混用：

// ① 直接给函数值 —— 最常用
vg_button_on_click(btn, on_click);

// ② 函数 + 预置实参：后面多写的都会在触发时排在事件参数前面
any_t func say(who) { output(who); }
vg_button_on_click(btn, say, "你好");      // 点一下 → say("你好")

// ③ 函数引用 &(?)f(...)：编译成 [函数, 参数...] 这样一个数组
vg_button_on_click(btn, &(?)say("世界"));    // 点一下 → say("世界")

// ④ 字符串函数名：触发时再回查函数表
vg_button_on_click(btn, "say", "字符串写法");
③ 和 ② 可以混着写：vg_button_on_click(btn, &(?)f(1), 2) 触发时是 f(1, 2)——函数引用自带的排在前面，绑定点后面多写的接在它后面。

3. 参数顺序：绑定参数在前，事件参数在后

触发的那一刻，VM 拼出来的实参表永远是这个顺序：

[ 绑定时预置的参数... ] + [ 事件自带的参数... ]

// 例：滑块 + 一个预置参数
any_t func on_vol(name, value) {
    output(name);      // "音量"   ← 绑定时给的
    output(value);     // 0.7      ← 滑块自己带的
}
vg_slider_on_changed(sl, on_vol, "音量");

// 例：下拉框 + 两个预置参数 → on_pick(a, b, index, text)
vg_combobox_on_selected(cb, on_pick, "A", "B");
⚠️ 最容易踩的坑：参数多了是从「前面」丢，不是从后面丢。
QOT 的函数调用允许实参比形参多，多出来的会从头部开始丢弃，只保留最后 N 个。 所以下面这段不会报错，但结果和你想的相反： 
any_t func on_pick(index) { output(index); }
vg_combobox_on_selected(cb, on_pick);   // 实际传入 (index, text)，多了 1 个
// → 前面的 index 被丢掉，形参 index 收到的其实是 text！
对策：形参个数一定要写满（绑定参数 + 事件参数），宁可写一个用不上的形参占位， 也不要少写。参见 语言文档 §22.2。

4. 其它注意事项

⚠️ 注意：回调函数是在 GUI 事件循环中被调用的，不要在里面执行耗时操作或阻塞等待， 否则会导致界面卡顿。如需执行耗时任务，建议使用异步方式或在回调中只做轻量级操作。
  • 绑定存的是函数值本身，不是名字。所以同名的嵌套函数不会互相顶掉 （写法 ④ 的字符串除外，它是靠名字回查函数表的）。QOT 没有匿名函数， 回调必须是一个具名 func。
  • 同一个控件重复绑定会覆盖，只有最后一次生效，不会累积成多个监听器。
  • 要跨回调保存状态，直接用顶层 var 全局变量就行—— VM 上函数内部对全局变量的赋值是生效的（这一点和 Python 解释器相反， 见 语言文档 §21）。
  • 回调必须在 vg_run() 之前绑定好；vg_run() 会一直阻塞到窗口关闭。

🎨 颜色格式说明

紫色 [0.55, 0.36, 0.96, 1]
蓝色 [0.38, 0.65, 0.98, 1]
绿色 [0.2, 0.83, 0.6, 1]
红色 [0.97, 0.44, 0.44, 1]
黄色 [0.98, 0.75, 0.14, 1]
// 颜色使用数组 [r, g, b, a]，取值范围 0-1
颜色 = [1.0, 0.0, 0.0, 1.0]      // 纯红色
半透明蓝 = [0.2, 0.4, 0.8, 0.5]    // 半透明蓝色
主题蓝 = [0.2, 0.6, 1.0, 1.0]       // QTC 主题蓝色
⚠️ 颜色只认数组，不认别的。
  • 传字符串（"#ff0000"、"red"）、数字、null—— 一律当成不透明黑色 [0,0,0,1]，不报错、不警告。
  • 数组少于 4 个元素时，缺的 r/g/b 补 0，缺的 a 补 1。 所以 [1, 0, 0] 就是不透明纯红，可以省掉 alpha。
  • 取值范围是 0–1 的小数，不是 0–255。写 [255, 0, 0, 1] 也不会报错，只是被显卡钳到最亮，等价于 [1,0,0,1]。

📦 完整示例：登录界面

// ========== 登录界面示例 ==========

vg_init();

var window = vg_create_window("登录", 400, 300);

// 渐变背景（窗口函数不传 window ID）
var start = [0.08, 0.08, 0.15, 1];
var end   = [0.12, 0.10, 0.20, 1];
vg_set_window_bg_gradient(start, end);

// 用户名输入框
var username = vg_create_textbox(100, 80, 200, 35, "用户名");

// 密码输入框
var password = vg_create_textbox(100, 130, 200, 35, "密码");

// 登录按钮
var login_btn = vg_create_button(100, 190, 90, 35, "登录");
var cancel_btn = vg_create_button(210, 190, 90, 35, "取消");

// 登录逻辑
any_t func do_login() {
    var user = vg_textbox_get_text(username);
    var pwd  = vg_textbox_get_text(password);
    
    if (user == "admin" && pwd == "123456") {
        output("登录成功！");
    } else {
        output("用户名或密码错误");
    }
}

any_t func do_cancel() {
    vg_textbox_set_text(username, "");
    vg_textbox_set_text(password, "");
}

vg_button_on_click(login_btn, do_login);
vg_button_on_click(cancel_btn, do_cancel);

vg_show_window();
vg_run();
vg_uninit();
// 把上面的代码存成 login.qot，然后：
python index.py bstrust compile login.qot login.qtc
python index.py bstrust run login.qtc
最佳实践：
  • vg_init() → vg_create_window() → 建控件 → 绑事件 → vg_show_window() → vg_run()，顺序不能乱。 窗口没建之前建控件，只会拿到 null，而且不报错。
  • 对象 ID 是字符串，一定要用变量接住；vg_create_* 失败时返回的是 null， 拿去调后续函数只会静默返回 false。
  • 回调形参个数写满（绑定参数 + 事件参数），少写会从前面丢参数。
  • 回调里可以放心读写顶层 var 全局变量，VM 上是生效的。
  • 回调函数尽量简短，避免阻塞界面。
  • 颜色值建议定义变量复用，便于统一修改主题。
  • 程序退出前记得调用 vg_uninit() 释放资源。
  • vg_destroy(obj_id) 只是把 ID 从对象表里摘掉，控件本身还留在窗口上 （C++ 里那段释放逻辑是空的）。要让控件消失，用 vg_set_visible(obj_id, false)。
