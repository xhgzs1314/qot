QOT 扩展开发

原生插件开发

QOT 与原生代码之间有两条通路：通用 FFI 直接调用 C 符号， 原生插件 ABI 用固定契约注册函数。两者在解释器与原生程序上行为一致。

1. 两条通路怎么选

通路 适合 QOT 侧接口
通用 FFI 调用现成的系统库（user32.dll、libm 等），无需自己写 DLL ffi_load / ffi_sym / ffi_call / ffi_call_v
原生插件 ABI 自己写库，需要结构化的入参/出参、容器读写、错误上报 plugin_load / plugin_call / plugin_names / plugin_free

2. 通用 FFI

var lib = ffi_load("user32.dll");        // 失败返回 null
var sym = ffi_sym(lib, "MessageBoxA");    // 失败返回 null

ffi_call(sym, 0, 0.0, 0.0, 0.0, 0.0);    // 推断调用：参数与返回值按 f64
ffi_call_v(sym, types, ...);             // 显式类型调用
类型码 含义
void 无返回值
i32 / i64 32 / 64 位整数
f64 双精度浮点
str 字符串
ptr 指针

辅助函数：ffi_str(ptr) 读指针处的 C 字符串（有界 1MB）； ffi_ptr(x) 把字符串转成 NUL 结尾副本地址； ffi_free(lib) 卸载动态库； ffi_last_error() 取上一次错误文本。

参数上限：一次调用最多 8 个参数（含返回值位）。

3. 原生插件 ABI

插件是一个动态库，唯一依赖是公共头文件 ot-asset/c/plugin/qot_plugin_abi.h。它导出唯一入口 qot_plugin_init，在初始化时通过 api->reg 注册函数。

3.1 值模型

QOT 的值是 16 字节：1 字节标签 + 8 字节载荷。插件只能通过 api 访问值， 不要直接解引用载荷指针——那是宿主私有布局。

typedef struct qot_value {
    uint8_t t;          /* QOT_VT_NONE / NULL / BOOL / NUM / STR / ARR / DICT */
    uint8_t pad[7];
    union { double d; void *p; } u;
} qot_value;

3.2 宿主能力面（api）

类别 成员
构造 set_null / set_bool / set_num / set_str / arr_new / arr_push / dict_new / dict_set
读取 tag_of / num_of / bool_of / str_of / arr_len / arr_at / dict_get
错误 set_error（文本挂到 QOT 侧的 ffi_last_error()，本次 plugin_call 返回 null）
注册 reg(name, fn, argc, doc)——仅在 qot_plugin_init 内调用；名字全局唯一

字符串内容是借用引用（非 NUL 结尾，以长度为准），只在本次调用内有效； set_str 是拷贝。容器由宿主持有，值可自由拷贝。

3.3 写一个插件

#include "qot_plugin_abi.h"

static void add(qot_value *ret, const qot_plugin_api *api,
                const qot_value *args, int argc)
{
    api->set_num(ret, api->num_of(&args[0]) + api->num_of(&args[1]));
}

QOT_PLUGIN_EXPORT int qot_plugin_init(const qot_plugin_api *api)
{
    int n = 0;
    n += api->reg("add", add, 2, "sum of two numbers");
    return n;            /* = 注册个数（契约） */
}

编译（Windows）：

g++ -shared -I ot-asset/c/plugin my_plugin.c -o my_plugin.dll

3.4 从 QOT 调用

var h = plugin_load("my_plugin.dll");        // 装载 → 句柄（失败 null）
output(plugin_names(h));                // ["add"]（注册序）
var r = plugin_call(h, "add", [2.0, 3.0]);
output(r);                              // 5.000000
plugin_free(h);                          // 卸载，其注册一并失效

4. 契约要点

  • 初始化契约：qot_plugin_init 的返回值必须等于 api->reg 成功注册的次数，否则宿主判定初始化失败并回滚；负数表示插件自认失败（宿主卸载并报错）。
  • 调用契约：插件函数必须写返回值出参 ret（不写就写 null）； args 只读，且只在本次调用内有效。
  • 线程契约：插件函数只会在装载它的主线程被调用，不要把宿主指针交给其它线程。
  • 版本协商：ffi_abi_version() 返回当前 ABI 版本（v2）； 插件可据此判断宿主能力。
  • 可移植性：只用 api 访问值，插件就能在解释器与原生程序上行为一致。

5. 常见问题

现象 原因与处理
plugin_load 返回 null 路径不对、缺依赖、或导出的入口名不是 qot_plugin_init；用 ffi_last_error() 看原因
plugin_call 返回 null，但函数确实存在 插件内部调用了 api->set_error；错误文本在 ffi_last_error()
参数读出来是乱码 字符串是借用引用且非 NUL 结尾——必须用 api->str_of(v, &len) 并按长度处理
进程崩溃 越界访问了 args（实参个数由 argc 决定），或直接解引用了值的载荷指针
