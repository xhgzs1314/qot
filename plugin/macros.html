编译期宏

宏在编译期把一段代码改写成另一段代码。写宏的语言就是 QOT 本身： 宏体是普通 QOT 函数，参数收到的是实参的语法树节点，返回值就是改写产物。 展开发生在字节码生成之前，因此产物与手写等价代码同价——没有运行期开销，也没有新的解释层。

1. 声明与调用

macro twice(x) {
    return < "kind": "binary_op", "op": "+", "left": x, "right": x >&;
}

var n = twice!(21);        // 展开一次 → 21 + 21
output(n);                 // 42
  • macro 声明只能写在顶层（函数体内声明 = 编译期致命）。
  • 调用写作 名字!(实参…)。! 是宏调用与逻辑非的分界： 标识符后紧跟 !( 是宏调用，表达式前缀位是逻辑非。
  • 宏名与变量名、函数名互不干扰（不同命名面）；同名宏重复声明 = 编译期致命。

2. 两种形态

2.1 表达式宏

宏返回一个节点 → 用在表达式位置。

macro inc(x) {
    return < "kind": "binary_op", "op": "+",
              "left": x, "right": < "kind": "literal", "value": 1 >& >&;
}
var v = inc!(41);          // 42

2.2 语句块宏

宏返回一个数组 → 产物是一串语句，用在语句位置。调用点还可以直接带一个块， 块内容以语句列表绑定到最后一个形参。

macro repeat(n, body) {
    var out = [];
    var i = 0;
    loop (i < n) {
        out = arr_concat(out, body);
        i += 1;
    }
    return out;
}

repeat!(3) {
    output("hi");          // 输出三次
}

控制流宏也走这个形态——下面的官方宏 unless! 就是「条件 + 块」：

unless!(n > 5) {
    output("不大于 5");
}

3. 参数收到的是什么

形参不是值，而是实参的语法树节点，以字典形式交给宏体：

< "kind": "节点类型", "字段名": ..., "line": 行号 >&

常见节点的字段：

kind 字段 说明
literal value 字面量（数字/字符串/布尔/null）
identifier name 变量名
binary_op op、left、right 二元运算
unary_op op、operand 一元运算（UMINUS / NOT）
function_call name、args 函数调用（args 是数组）
method_call receiver、name、args 方法调用
array elements 数组字面量
dict entries 字典字面量；每个 entry 是数组 [键值, 值值]
var_declaration name、value 变量声明
assignment name、value 赋值
if_statement condition、then_body、else_body 条件语句
return_statement value 返回语句
block body 语句块

宏自己造节点时，不需要写 line——展开器会自动补上调用点的行号， 于是宏体内的报错能精确定位到调用位置。

造字典字面量节点时，entry 写成数组：< "kind": "dict", "entries": [[k, v], [k2, v2]] >&。

4. 嵌套与语义

4.1 实参先展开

macro quad(x) {
    return twice!(twice!(x));      // 内层先展开
}
var v = quad!(3);                 // 3 → 6 → 12

4.2 宏体内调用其它宏 = 值语义

宏体里写 other!(x) 时，x 先被求值成节点，再展开 other——等价于把 other 的展开结果代入 x。

macro inc(x)  { return < "kind": "binary_op", "op": "+", "left": x, "right": < "kind": "literal", "value": 1 >& >&; }
macro inc2(x) { return inc!(inc!(x)); }
var v = inc2!(40);                // 42

5. 官方宏

宏 作用 限制
swap!(a, b) 交换两个变量的值（真交换，不是返回元组） 实参必须是标识符
unless!(cond) { … } 条件为假时执行块（等价 if (cond) { } else { … }） 块绑定到最后一个形参 
var lo = 1;
var hi = 9;
swap!(lo, hi);
output(lo);        // 9
output(hi);        // 1

6. 错误契约

情形 结果
调用未定义的宏 编译期致命：宏 'x' 未定义
重复定义同名宏 编译期致命：宏 'x' 已定义
宏体执行出错 编译期致命，定位到调用点行号
宏返回了语言不认识的节点 编译期致命（会明确告诉你缺哪个字段）
表达式宏被用在语句位置 编译期致命（除非它返回的是调用节点，此时自动包成语句）

7. 上限

展开有上限，防止宏把自己写递归后无限膨胀：

限制 默认值 环境变量
展开深度 64 QOT_MACRO_DEPTH（0 = 不限）
单次编译总步数 1,000,000 QOT_MACRO_LIMIT（0 = 不限）

超限同样是编译期致命，错误信息里会写明是深度还是步数超限。

8. 卫生（重要）

QOT 宏不做卫生处理。宏体引入的名字与调用点是共享作用域的—— 宏里生成的临时变量可能捕获调用点的同名变量，调用点也可能覆盖宏里的临时变量。 这是刻意的取舍：简单、可预测，代价由写宏的人负责。

约定做法：

  • 宏体里的临时名用 _m_ 前缀（如 _m_i、_m_tmp）——下划线开头但不是双下划线。
  • 双下划线前缀 __ 是编译器保留的（隐藏临时变量、协议绑定产物、方法接收者改写）， 不要在用户代码里使用。
  • 尽量让宏体只使用形参与自己的临时名，不依赖外部变量。

9. 什么时候用宏

需求 推荐手段
复用一段固定代码形状 宏（macro）
给对象加运算/迭代/输出 协议方法（见协议元语）
一次性的重复代码 普通函数（更简单、更安全）
运行时才需要的行为差异 函数 + 字典分派，不要用宏
一个完整例子。用「协议 + 宏」在纯 .qot 里长出接口与多态： 
macro speak(x) {
    return < "kind": "method_call", "receiver": x, "name": "speak", "args": [] >&;
}
class Dog { func speak() { return "woof"; } }
output(speak!(Dog()));
